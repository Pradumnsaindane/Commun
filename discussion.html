What's the best way to structure a large Spring Boot multi-module project?

Hey everyone, our backend team is breaking down a legacy monolith into a hexagonal modular architecture using Gradle. Currently, we are discussing between two setups:

  • Option A: core-domain (pure POJOs with zero Spring dependencies) + infrastructure-db + api-web.
  • Option B: Feature-based modules (e.g., billing-module, auth-module, catalog-module) each containing their own ports and adapters.

How do you handle shared DTOs and cross-module transactions without causing circular dependency nightmares? Would love to hear lessons learned from production.

Sarah Jenkins 2h ago
Definitely go with Option A for core foundational libraries, but slice your business domains as feature modules (Option B). To avoid circular dependencies, modules must never talk directly to another module's database tables—they should publish domain events (via Spring ApplicationEvent or Kafka) or use clean interfaces exposed in a shared contract package.
Liam Keller 1h ago
One big caveat with multi-module Gradle builds: make sure to use api vs implementation dependencies deliberately in your build.gradle.kts so transitive dependencies don't leak across modules and slow down incremental compilation.
