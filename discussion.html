How to prevent deadlock in custom Kubernetes controller when watching MutatingWebhookConfigurations?

We run a multi-tenant operator written with controller-runtime in Go. When our admission webhook restarts or reconfigures its TLS certificates, it tries to patch its own MutatingWebhookConfiguration.

However, the API server intercepts this PATCH request and sends it back to the very webhook service that is currently acquiring the leader lease, resulting in a permanent timeout deadlock.

data_object webhook_reconciler.go 
func (r *WebhookReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
    // Hangs here during leader election restart
    if err := r.Client.Patch(ctx, &mutatingCfg, client.MergeFrom(original)); err != nil {
        return ctrl.Result{}, fmt.Errorf("deadlock waiting for admission: %w", err)
    }
    return ctrl.Result{}, nil
}

The standard production pattern in Kubernetes admission webhooks is to add a namespace selector or object selector on the webhook configuration that explicitly excludes the operator's own namespace and objects:

Add namespaceSelector.matchExpressions with operator.commun.dev/exclude: "true". Additionally, set failurePolicy: Ignore for the operator's own config endpoints during bootstrap.

data_object webhook.yaml 
namespaceSelector:
  matchExpressions:
    - key: "kubernetes.io/metadata.name"
      operator: NotIn
      values: ["operator-system"]
